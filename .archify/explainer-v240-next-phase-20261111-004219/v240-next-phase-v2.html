AstraFlow 2.4.0: what remains?

Long image

A

Answer

The approved 2.4.0 source work and local release checks are complete. The maintainer chose to keep the branch local, so Phase 4 remote checks remain pending. Version 2.4.0 is still unpublished.

  1. Phase 1 established the runner-neutral AstraFlow.Assertions package and migrated AstraFlow's test projects.
  2. Phase 2 added inherited-property, nullable-scalar, positional-record, primary-constructor, and init-only generated mappings.
  3. Phase 3 passed the local build, tests, package, consumer, API, upgrade, and reproducibility gates.
  4. Local diff review passed. Phase 4 still needs hosted CI and remote SourceLink evidence before the release is ready.

Applies toLocal branch evidence on 2026-11-11; hosted checks and publication are not included

What changes for an existing 2.3.0 app?

Adoption choiceExpected project edits
Upgrade existing AstraFlow packagesUpdate the package versions already referenced, then restore, build, and run the application's tests. No source rewrite is expected for existing APIs.
Use AstraFlow assertionsAdd AstraFlow.Assertions to the test project and change only tests that adopt its API. Production projects need no new dependency.
Use the new generated mapping shapesUpdate only explicitly declared mapping methods that need inherited entity fields or immutable DTO construction. Existing mappings stay opt-in and do not switch automatically.
