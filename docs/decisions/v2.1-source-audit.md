# v2.1 generated mapping source audit (draft)

Base: `9747494d68d9288841675024a58d0472bd4db7a6`; base source version and latest local tag: 2.0.0. The roadmap identifies generated execution as the v2.1 release objective. Published Mapper and Generators 2.0.0 packages were independently obtained from NuGet for compatibility work; the local draft has not been published.

The existing `AstraFlowObjectMapper` checks null and assignability, then collections before mapping rules; mapper and rule registrations are scoped. `AstraFlowMapperMetadataGenerator` emits metadata and uses a compilation-wide scan. The new route is a direct typed method and does not participate in those runtime semantics or registration. No adapter is proposed here.

A partial method is the v2.1 public API because its declaration is also the typed call site: the compiler checks source and destination types, the generated implementation attaches to the exact method, and consumers need no runtime registry or `IMapper` adapter. A type-pair catalog would still need either a generated per-pair method naming contract or a dispatch/registration API; the latter would add an indirect execution path and runtime ownership/lifetime questions that the narrow v2.1 goal does not need. This trade-off keeps generated execution separate from `IMapper` and opt-in at every call site. A dedicated alternative prototype is not required to validate this API boundary, but package/API compatibility gates still apply before release.

The draft deliberately rejects complex construction and member shapes. The generator links the shared default security policy source so it does not depend on loading a separate runtime assembly as an analyzer dependency; it cannot evaluate configured runtime policies. Sensitive-name detection is defense in depth, not authorization.

Verification has progressed beyond the initial preview-SDK tests: stable SDK 10.0.400 has run the solution restore, Release build and regression tests, local package consumers, and a Native AOT publish and executable for generated mapping. Final-pass package hashes, benchmarks and the limitations of each check are recorded in [draft evidence](v2.1-draft-evidence.md) and the PR. The XML member-ID comparison and Mapper package validation do not establish binary compatibility for every package. The public API decision and 2.1.0 draft metadata are now recorded; the PR remains Draft because the broader mediator AOT path and several release gates have limitations documented in the evidence report.
