# v2.1 generated mapping source audit (draft)

Base: `9747494d68d9288841675024a58d0472bd4db7a6`; base source version and latest local tag: 2.0.0. The roadmap identifies generated execution as the v2.1 release objective. Published Mapper and Generators 2.0.0 packages were independently obtained from NuGet for compatibility work; the local draft has not been published.

The existing `AstraFlowObjectMapper` checks null and assignability, then collections before mapping rules; mapper and rule registrations are scoped. `AstraFlowMapperMetadataGenerator` emits metadata and uses a compilation-wide scan. The new route is a direct typed method and does not participate in those runtime semantics or registration. No adapter is proposed here.

A partial method was selected for the draft because the call site is explicit, typed and discoverable; a type-pair catalog would additionally require a generated call naming or registration convention. A comparative prototype and API compatibility review remain outstanding, so this is not a final public API decision. The draft deliberately rejects complex construction and member shapes. The generator links the shared default security policy source so it does not depend on loading a separate runtime assembly as an analyzer dependency; it cannot evaluate configured runtime policies. Sensitive-name detection is not authorization.

Verification has progressed beyond the initial preview-SDK tests: stable SDK 10.0.400 has run solution restore, build and regression tests, local package consumers, and a Native AOT publish and executable. The latest generator suite, package hashes, benchmarks and the limitations of each check are recorded in [draft evidence](v2.1-draft-evidence.md) and the PR. The XML member-ID comparison and upgrade smoke do not establish complete binary compatibility; final-source full verification, more reliable performance measurements, release metadata and the public API decision remain open.
