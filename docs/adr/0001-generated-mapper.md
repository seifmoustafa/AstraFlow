# ADR-0001 — Generated runtime mapping (proposed)

**Status: proposed; API sketches are not shipped APIs.**

## Context
Existing generators emit mediator DI registration and mapper/projection metadata. Neither is a generated object conversion runtime path. Current explicit and convention mapper paths must remain stable.

## Preferred experiment
Investigate a typed, statically declared map generated by an incremental Roslyn generator, with the smallest additive declaration possible. Compare a partial-method attribute declaration with a type-pair registration approach *against the actual mapper APIs* before committing. A generated method is an example of an interface, not a promise.

First slice: public, accessible, exactly matched, type-compatible scalar members to an unambiguous mutable destination. Keep required-member, nullability and sensitive-data checks. Unsupported rules emit stable, source-located diagnostics. No deep graphs, dynamic resolvers, arbitrary custom expressions, EF SQL compilation or polymorphic updates.

## Execution and registration
Direct typed calls may have different cost than existing IMapper calls. Optional generated DI adapter only after inspecting IObjectMappingRule ownership and duplicate validation. Generated-only behavior must fail on unsupported shapes, never silently fall back. Existing runtime explicit/convention behavior remains independently available.

## Safety and correctness gates
- Compile a clean consumer from packaged generator assets.
- Deterministic output and repeat builds; verify incremental edits.
- Negative tests for required/init members, ambiguity, inaccessible constructors, null mismatch, unsafe conversions, sensitive writes, duplicate pairs and unsupported shapes.
- Differential correctness tests where the declared semantics overlap existing mapper.
- Native AOT publish and execute, inspect trim warnings.
- Measure cold start, steady-state mappings, allocations, DLL size, generator incremental build time, and peer baseline on the same environment.
- Any public API change follows API governance and migration rules.

## Trade-offs
Generated mapping improves analyzability but can increase source/build size, and cannot know runtime DI/delegate behavior. A small supported subset is preferable to an opaque or misleading broad one.

**Decision gate:** inspect current sources and write down chosen API, output shape, registration ownership and unsupported-shape policy before implementation.
