# v2.1 — Generated mapping execution release plan

**Status:** proposed single-release implementation contract. **Not shipped.** Existing roadmap's performance lane remains, narrowed to a measurable execution slice.

## Scope
One deterministic source-generated *typed* object conversion for explicitly declared simple DTO mapping; source-located unsupported-shape diagnostics; zero change to explicit-core defaults, opt-in conventions or published contracts. Optional IMapper adapter is conditional on repository review. This is *runtime execution*, not metadata generation.

## First checks
Inspect IMapper, IObjectMappingRule, DI registration ownership, duplicate detection, generator inputs and consumer tests. Pin SHA and versions. Run restore/build/test/pack/install and sample suite; record existing API and baseline output. Document ADR declaration choice before coding.

## Implementation order
1. Select minimum declaration API against existing architecture.
2. Add golden generator tests + diagnostics for unsupported members and source locations.
3. Emit readable compile-valid mapping for accessible same-name assignable scalar properties.
4. Apply nullability/required/sensitive policies and duplicate mapping checks.
5. Integrate only if semantically safe with current mapper registration.
6. Add clean multi-target consumer, AOT publish **and run**, snapshots and differential correctness tests.
7. Benchmark against manual mapping, runtime AstraFlow, and selected competitor APIs. Record allocations, generator/build cost and resulting binary size.
8. Docs, migration examples, changelog, API baseline, package asset/install checks; completion report and maintainer review.

## Acceptance
No silent fallback or security bypass; no hidden default conventions; no payload logs; documented source/runtime boundaries; deterministic output; meaningful diagnostics; compatible existing samples; AOT warnings reviewed; measured results not marketing estimates.

## Not in this release
Generated mediator runtime, deep graphs, arbitrary runtime delegates/DI resolvers, projected SQL generation, polymorphic collections, dashboards, auth, background jobs.

## Ownership and decision
Maintainer must identify owner and close architecture spike before public API approval. Next version begins only after review of completed test/benchmark evidence.
