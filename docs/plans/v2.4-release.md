## Phase 1 — Assertions foundation

The current source adds `AstraFlow.Assertions`, a runner-neutral package with an AstraFlow-owned implementation and no shipping package dependencies. The existing internal assertion call sites have been migrated. Its published capability must be described by the actual API and tests; this release plan does not claim universal parity with other assertion libraries.

Recorded local evidence and current capability limits are maintained in [the assertion plan](v2.4-assertions.md) and [the assertion guide](../assertions.md).

## Phase 2 — Enterprise generated mapping

### User problem

The existing executable mapping generator rejects common domain/read-model shapes: entity properties inherited from a generic audit base, `Guid`/`DateTime`/`DateTimeOffset` and nullable value scalars, and immutable record or primary-constructor DTOs. Consumers should be able to declare one typed mapping method without wrapper POCOs or string conversions.

### Required behavior

- Recognize enum and existing primitive scalar types plus `Guid`, `DateTime`, and `DateTimeOffset`.
- Support nullable value scalar assignments when the value flow is safe: `T -> T?` and `T? -> T?`. Reject `T? -> T` unless a later explicit conversion feature defines its null behavior.
- Find public readable source properties through the class hierarchy, including a closed generic audit base such as `AuditableEntity<Guid>`. Reject ambiguous hidden properties; do not guess between them.
- Support positional record and primary-constructor destinations by matching every required constructor parameter to one public readable source property, case-insensitively. Require compatible types/nullability, reject ambiguous constructor selection, and preserve constructor parameter order.
- Support public init-only destination properties through an object initializer when an accessible parameterless constructor is selected.
- Retain sensitive-name blocking, located `AFM001` errors, deterministic output, cancellation, and incremental invalidation when inherited members or constructor shapes change.
- Do not silently add numeric conversions, nested object mapping, domain writes, or runtime/convention fallback.

### Acceptance evidence

1. Roslyn tests compile and execute a derived entity to positional record mapping with inherited `Guid Id`, `DateTime CreatedAt`, a `DateTime?` field, and a string property.
2. Nullable coverage includes `decimal?`, `int?`, `Guid?`, `DateTime?`, `T -> T?`, `T? -> T?`, null preservation, and a negative `T? -> T` case.
3. Init-only record and C# primary-constructor shapes compile; ambiguous constructors, missing properties, unsafe nullability, and sensitive destination names report `AFM001` without generated code.
4. An incremental-generator test proves that edits to inherited properties and constructor parameters invalidate the affected mapping.
5. Generator build and tests pass without warnings; Release package pack and a clean consumer compile the emitted API.
6. Documentation states the exact supported and rejected shapes. Performance or “zero-allocation” claims require a separate benchmark with a stated allocation scope.

## Explicitly outside the committed 2.4.0 scope

- Generated mediator dispatch remains a candidate governed by [ADR-0002](../adr/0002-generated-mediator.md); it is not silently promoted into this release.
- Broad nested mapping, reverse/domain writes, runtime-policy inference, and arbitrary conversions remain outside this generator phase.
- Future assertion families and differentiation work remain separate decisions; Phase 1 must not be described as complete source/behavior parity with another package.
- The graph, Canvas JSON and generator collection changes already in the 2.3.0 baseline are not new 2.4.0 deliverables.

Remote SourceLink checksum mode reached GitHub but returned 404 for the 17 `AstraFlow.Assertions` source documents in the symbol package: its URLs point at the current base commit, which predates these uncommitted files. The full remote-source gate therefore cannot pass until the branch's source exists at a remote commit.

The maintainer has authorized publishing the branch and opening a PR if checks are clean. Hosted CI and remote SourceLink remain pending until the source commit is pushed.
