# v2.4 — Generated Mediator Dispatch Candidate Plan

> **Candidate, NOT an approved release guarantee.** Existing v2.2 supply-chain and v2.3 API-governance roadmap lanes must not be silently displaced. Work starts only after v2.1 review and an explicit go/no-go decision.

## Objective
Determine whether AstraFlow can offer a reliable compile-time generated **closed request/response dispatch execution** route with improved performance/AOT characteristics while preserving existing mediator behavior and DI lifetimes.

## Baseline discovery already supported by source

The current [mediator](../../src/AstraFlow.Mediator/AstraFlowMediator.cs) caches request-type dispatch delegates in a static `ConcurrentDictionary`; reflection closes core methods when first seen, and the mediator holds a scoped `IServiceProvider`. The plausible generated win may be first-use latency and AOT behavior, not necessarily warmed dispatch throughput. Treat this as the **hypothesis to falsify** with a direct/current/generated comparison.

## Ordered research and implementation gates

1. **Repository audit:** inspect existing handler wrapper caching, `ISender.Send` typed/object, request/void/stream/notification dispatch, registration, behavior/processor order and exception semantics.
2. **Benchmark first:** direct handler, current AstraFlow runtime and candidate generated strategy; same request body, handlers, DI scopes and pipeline depth. If runtime path is already adequate, optimize/defer rather than generating code for its own sake.
3. **Single invoker proof:** implement one closed typed request/response route; no broad new abstraction. Generated-only unknown types fail predictably.
4. **Behavior parity:** regression tests for nested pipeline order, short-circuit, cancellation, exception handling/actions, rethrows and handler scope/disposal.
5. **Compiler package:** deterministic generated output, stable diagnostics, incremental edits, multi-assembly constraints and clear generated vs runtime provenance.
6. **Deployment:** clean consumer install, AOT publish **and run**, trim-warning review and binary-size comparison.
7. **Release:** public API diff, migration guidance, docs, changelog, benchmark data and maintainer review.

## Required failure matrix
Missing/duplicate handler; ambiguous request contract; null and object dispatch; closed vs open generics; cancellation before/during dispatch; nested scopes; disposed handlers; multiple pipelines; processor order; exception handlers with handled-state contracts; parallel requests; package install without generator.

**Out of scope:** durable messages, broker transactions, outbox, background jobs, workflow engines, retry/Polly replacement, generated streaming/notifications in the first slice.

**Stop condition:** no meaningful consumer benefit after realistic benchmarks, or unacceptable build/runtime/DI complexity. See [ADR-0002](../adr/0002-generated-mediator.md).
